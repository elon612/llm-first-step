# 05. 模型是怎么训出来的（懂原理，不用动手）

你不需要自己训练模型。但你每天在用的模型的很多行为，只有从训练过程才能解释：

- 为什么它会按格式调用工具？
- 为什么写代码比写事实性内容可靠？
- 为什么它总说“好的，您说得对”，甚至附和你的错误判断？
- 为什么有的模型会“先想一会儿”？

## 一条流水线

```text
预训练        海量文本上做 next-token       → 会续写：代码、文档、对话都会“接着写”
    ↓
SFT           人写的“指令 → 好回答”样本     → 会按指令回答、会按格式输出工具调用
    ↓
RLHF / DPO    人类偏好打分                  → 更礼貌、更有帮助；副作用：讨好、啰嗦
    ↓
RL（可验证奖励） 代码跑通、数学答对才给奖励  → reasoning 模型、强 coding 能力
```

看 Karpathy — [Deep Dive into LLMs like ChatGPT](https://www.youtube.com/watch?v=7xTGNNLPyMI)，
这条流水线的每一步它都讲了。

## 把行为对回训练

| 你看到的行为 | 来自哪一步 |
| --- | --- |
| 知道 Flutter 怎么写，但写的是旧 API | 预训练：旧版本资料多，且有截止日期 |
| 编造不存在的包名 | 预训练：学的是“看起来合理的续写”，不是查表 |
| 能输出合法的工具调用 JSON | SFT + RL：专门用工具调用样本训练过 |
| 附和你的错误判断 | RLHF：人类打分时偏爱“同意我”的回答 |
| 写代码、修 bug 越来越强 | RL：测试通过就是天然的奖励，可以大规模自动训练 |
| 写 UI 不如写逻辑稳 | RL：“界面好不好看”很难自动打分，奖励信号弱 |
| reasoning 模型先想再答 | RL：先生成推理 token 再给答案，答对得奖励，于是学会了“多想” |

最后三行解释了一件对你很实用的事：**模型在“结果可验证”的任务上最强**。
所以把任务改造成可验证的（给测试、给 analyzer），就是在借模型最强的那部分能力。

## reasoning 模型什么时候用

reasoning token 要花时间，也要花钱（第六课）。

| 值得 | 不值得 |
| --- | --- |
| 架构设计、跨模块重构方案 | 改文案、改颜色、加字段 |
| 排查原因不明的 bug | 按明确步骤的机械修改 |
| 读陌生代码后写计划 | 格式化、改名 |

## 你需要自己微调吗？

对“用 agent 写代码”这件事：几乎不需要。前沿模型已经被厂商大规模后训练过，个人微调很难超过它们。

先按这个顺序排查：

```text
行为不对    → 先改上下文（第三课）
缺少知识    → 给文档 / 检索（第三课、第七课）
还是不行，且有大量高质量样本，且要用小模型压成本/延迟 → 才考虑微调
```

几个名词只需一句话：

- **LoRA**：不改原始权重，只训一小组附加矩阵，所以便宜
- **蒸馏**：大模型生成数据教小模型；各家的 mini / flash 模型大多这么来
- **MoE**：模型总参数很大，每个 token 只激活一部分“专家”，所以大模型也能便宜地跑

## 这一课结束的标准

- 能按顺序说出四个训练阶段，每个阶段一句话说清它改变了什么行为
- 能用训练过程解释“为什么给测试让 agent 更可靠”
- 能说出一个值得用 reasoning 模型的任务和一个不值得的任务
